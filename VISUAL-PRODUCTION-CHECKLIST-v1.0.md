## A. Global Visual Rules

### A1. Palette
- Navy #1B2040 — headings, anchors, high-importance labels
- Teal #3C8C86 — navigation, active state, positive progress
- Coral #D7655F — caution, contradiction, review point
- Mustard #D8A23A — hints, uncertainty, teacher note
- Warm Cream #F6F0E5 — page / slide background
- Soft Gray #ECEBE7 — secondary panel

### A2. Visual Language
Use:
- notebook paper
- clipboard
- worksheet
- sticky note
- index card
- evidence card
- simple table
- simple chart
- reasoning diagram

Avoid:
- cyber dashboard
- sci-fi / neon / glassmorphism
- decorative stock-photo dependence
- dense infographic
- tiny text embedded inside raster images

### A3. Mobile-first Rule
For GitHub Lab:
- one dominant visual per question/stage
- visual placed above the response field
- 44px+ touch targets
- cards stack vertically on small screens
- tables use horizontal scroll only when unavoidable
- use card alternative for wide tables
- visual caption <= 2 lines
- no hover-only meaning

### A4. Evidence Labels
Use:
- "Master Case: โรงเรียนอรุณพัฒนา" for approved case data
- "Synthetic Teaching Dataset" for training datasets
Never mix the two labels.

# F. Acceptance Gate for Visual Build

PASS only if:
- every question/stage has one meaningful visual component;
- visuals directly support the learner task;
- all numeric visuals match approved datasets;
- synthetic data are labeled;
- Master Case data are labeled;
- mobile layout is readable;
- no visual causes horizontal page overflow;
- visual information is not available by color alone;
- visual assets do not introduce unverified facts;
- page remains lightweight and static-first.
